# Тойға — люди для вашего события

Локальное веб-приложение для хакатон-задачи **«Умный подбор подрядчиков #79-lite»**. Помогает выбрать до трёх event-подрядчиков из каталога по городу, дате, формату и бюджету. Каждая рекомендация содержит проверяемое объяснение.

Интерфейс на русском: светлая палитра, зелёные и терракотовые акценты, адаптивная сетка, избранное и календарь занятости. Фотографии и отзывы не выдумываются: профили оформлены монограммами.

> **О данных:** по умолчанию приложение использует предоставленный CSV — `data/hackathon.csv`: **66 профилей**, из них 53 с `synthetic: false` и 13 с `synthetic: true`. Исходные имена, описания, цены, занятость и флаги сохранены. Отдельный набор из 66 собственных синтетических демопрофилей доступен для дополнительной демонстрации.

## Быстрый запуск

Нужен **Python 3.9+**. Зависимости, npm, база данных и API-ключи не требуются.

```bash
cd hack-9c881983-rabi-gulnaz
python3 server.py
```

Откройте **http://127.0.0.1:8000**. Первая подборка выполняется автоматически. Остановить сервер: `Ctrl+C`. На Windows вместо `python3` можно использовать `py`.

Если порт занят:

```bash
python3 server.py --port 8080
```

Для другого датасета:

```bash
python3 server.py --data /полный/путь/catalog.csv
# Также поддерживается JSONL:
python3 server.py --data /полный/путь/catalog.jsonl
```

По умолчанию сервер доступен только на этом компьютере. Это локальный прототип без авторизации. Шрифт Golos Text загружается из Google Fonts; без интернета используется системный шрифт. Подбор и остальные функции не требуют внешних сервисов.

## Возможности

- Обязательные параметры: город, дата, тип события, категория и бюджет в тенге.
- Опциональные параметры: длительность и язык.
- До трёх карточек с именем, категорией, городом, ценой и объяснением.
- Исключение занятых подрядчиков, включая площадки, до ранжирования.
- Проверка формата, бюджета, языка и предельной длительности.
- Три исхода: **подобрали**, **в городе нет категории**, **категория есть, но никто не проходит условия**.
- Объяснение недостатка результатов и список исключённых профилей с причинами.
- Сравнение одной заявки на две даты с объяснением изменений.
- До трёх ближайших подходящих дат, если на исходную дату нет результатов. Все остальные условия сохраняются.
- Избранное в `localStorage` браузера.
- Детальная карточка с исходным описанием, календарём и флагами качества данных.
- Проверка и загрузка CSV или JSONL, возврат к исходным 66 профилям.
- Четыре демонстрационных сценария под формой.
- Адаптивная вёрстка, подписи полей, управление с клавиатуры, сообщения об ошибках.

Бронирование, отправка заявок и уведомления отсутствуют согласно заданию.

## Алгоритм

```text
Валидация заявки
        ↓
Город + категория → исходный пул
        ↓
Проверка каждого профиля:
  дата ∉ busy_dates
  price_from_kzt ≤ бюджет
  формат ∈ event_formats
  язык ∈ languages, если указан
  max_hours ≥ длительность, если оба заданы
        ↓
Стабильная сортировка прошедших профилей
        ↓
До 3 карточек + объяснения + причины исключений
```

### Ограничения

Дата должна быть в окне **23.09.2026–31.12.2026**. За пределами окна сервис возвращает ошибку и не объявляет подрядчиков свободными. Бюджет — конечное положительное число до 1 млрд ₸; длительность, если задана, — больше 0 и не больше 24 часов.

`max_hours: null` означает отсутствие привязки к присутствию. Флорист с `null` подходит при запросе шести часов; это не обещание шести часов работы на площадке.

Причины исключения независимы: профиль может одновременно быть занят и превышать бюджет. Сумма счётчиков причин иногда больше числа исключённых профилей. Интерфейс объясняет это.

### Ранжирование

Ключ сортировки: `(price_from_kzt, количество event_formats, id)` по возрастанию.

1. Среди полностью подходящих сначала показываются более доступные по исходной цене.
2. При равной цене — более узкая специализация по форматам. Это прозрачная эвристика, а не доказательство качества.
3. Последнее разрешение равенства — строковый ID.

Случайности, LLM и скрытых процентов совпадения нет. Повторный запрос даёт тот же ответ; перестановка входных записей не меняет выдачу. Порядок исключённых профилей также стабилен.

### Объяснения

Пример для Хаула: «От 1 000 000 ₸ — ровно в пределах бюджета; формат “свадьба”; на 17.10.2026 дата не отмечена занятой в каталоге. Из описания: “Профессиональный ведущий с интеллигентной, располагающей и ненавязчивой подачей”».

Цена, остаток бюджета, формат, язык и часы берутся из профиля и заявки. Второе предложение содержит дословный фрагмент описания: сначала выбирается фраза с упоминанием формата, иначе — первая содержательная фраза. Длинный фрагмент сокращается до 180 символов с многоточием. Это помогает различать профили с одинаковой ценой, но не является независимой проверкой утверждений автора. Полное описание доступно в подробной карточке. Сервис не приписывает подрядчику отзывы, оценки, опыт или услуги, которых нет в записи.

Цена «от» — нижняя граница, а не итоговая смета. Отсутствие занятой даты — факт из датасета, а не подтверждение бронирования. Эти пояснения доступны в интерфейсе.

## Демонстрация для жюри

Используйте кнопки под формой. Результаты ниже проверены на исходном `data/hackathon.csv`. Если явно не указаны, язык и длительность оставлены пустыми.

| Сценарий | Параметры | Ожидаемый результат |
|---|---|---|
| Плотная категория | Алматы, 17.10.2026, свадьба, Ведущий, 1 000 000 ₸ | Подходят 3 из 10: Эмилия (`HK-42352`), Кики (`HK-35215`), Хаул (`HK-77838`) |
| Другая дата | Та же заявка, 18.10.2026 | Подходят 4 из 10; первые 3: Мицури Канроджи (`HK-44923`), Кики (`HK-35215`), Сон Гоку (`HK-27222`) |
| Редкая категория | Алматы, 17.10.2026, свадьба, Флорист, 300 000 ₸, 6 ч | Один результат: Тихиро Огино (`HK-90001`); второй флорист занят; `null` часов не мешает подбору |
| Нет совпадений | Алматы, 17.10.2026, свадьба, Ведущий, 10 000 ₸ | Профили есть, но ни один не проходит бюджет |
| Нет категории | Зарубежье, Ведущий | Отдельное сообщение об отсутствии категории в городе |

Порядок защиты:

1. Нажмите **«Ведущие на свадьбу»**, прочитайте объяснения двух разных карточек.
2. Повторите подбор: порядок не изменится.
3. Откройте **«Сравнить с другой датой»** и сравните с 18 октября. Покажите имена и причины изменения.
4. Откройте **«Редкая категория»**: покажите один результат и причину исключения второго флориста.
5. Нажмите **«Небольшой бюджет»**, затем **«Нет категории в городе»**: покажите различие исходов.
6. Раскройте **«Прозрачный подбор»** и объясните исключения.
7. Покажите разделы **«Как это работает»** и **«Данные проекта»**, включая маркировку синтетических данных.

### Форматы импорта

В **CSV** первая строка содержит названия полей. Разделитель столбцов — запятая; поля с запятыми или переносами заключаются в кавычки по стандартным правилам CSV. Кодировка — UTF-8, допускается BOM.

- `categories`, `event_formats`, `languages`, `busy_dates` — значения через `|`, например `свадьба|той`.
- `synthetic`, `city_imputed`, `price_imputed` — `True` или `False` без учёта регистра.
- `price_from_kzt` — число; `max_hours` — положительное число или пустая ячейка, которая преобразуется в `null`.

В **JSONL** каждый профиль — отдельный JSON-объект на строке. Пример:

```json
{"id":"provider-001","anon_name":"Пример профиля","categories":["Ведущий"],"city":"Алматы","price_from_kzt":250000,"event_formats":["свадьба","той"],"languages":["русский","казахский"],"max_hours":6,"busy_dates":["2026-10-18"],"description":"Двуязычная программа с семейными церемониями.","synthetic":true,"city_imputed":false,"price_imputed":false}
```

ID должен быть уникальным. В JSONL категории, форматы, языки и даты — массивы строк; флаги — булевы значения. Для обоих форматов цена — неотрицательное число; `max_hours` — положительное число или `null`. Отсутствующие флаги получают `false`. Форматы и языки приводятся к нижнему регистру. Город и категория сопоставляются точно. Исходные описания сохраняются целиком и доступны в подробной карточке.

Лимиты интерфейса: 6 МБ и 5 000 профилей; лимит JSON-запроса API — 8 МБ. Импорт заменяет каталог сервера и очищает избранное текущего браузера. В других открытых вкладках нужно повторить подбор или обновить страницу.

Импорт из обоих форматов сохраняется в нормализованный `data/imported.jsonl`, исключённый из Git. Обычный перезапуск снова использует **исходный CSV**. Чтобы запустить сохранённый импорт:

```bash
python3 server.py --data data/imported.jsonl
```

### Дополнительные демоданные

Собственный синтетический набор хранится отдельно и не заменяет исходный CSV. Его можно запустить явно:

```bash
python3 server.py --data data/demo.jsonl
```

Воспроизвести этот набор:

```bash
python3 generate_demo.py
```

Генератор использует фиксированные seed для каждого ID. В сентябре–ноябре около 37% дней заняты, в декабре — около 76%; у ведущих и флористов есть фиксированные даты для воспроизводимой демонстрации. Это характеристики собственного демонабора. Проверенные сценарии выше относятся к исходному CSV.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | Фильтры, количество профилей, источник, ID каталога и счётчики флагов |
| POST | `/api/recommend` | Подбор и диагностика |
| POST | `/api/import` | Проверка и загрузка: `{"text":"...","format":"csv"}` или `{"text":"...","format":"jsonl"}`; без `format` ожидается JSONL |
| POST | `/api/original` | Возврат к исходному `data/hackathon.csv`: `{}` |
| POST | `/api/demo` | Подключение дополнительного синтетического демонабора: `{}` |

Пример:

```bash
curl http://127.0.0.1:8000/api/recommend \
  -H 'Content-Type: application/json' \
  -d '{"city":"Алматы","date":"2026-10-17","event_format":"свадьба","category":"Ведущий","budget":1000000,"hours":"","language":""}'
```

Ответ: `status` (`matched`, `no_category`, `no_matches`), нормализованный `query`, `cards`, `pool_count`, `eligible_count`, `excluded_count`, `reason_counts`, подробный `excluded`, `alternative_dates` и описание ранжирования. Ошибки данных — HTTP 400 с `error`; превышение размера запроса — HTTP 413.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют три исхода, предел в три карточки, детерминизм при перестановке датасета, смену даты, занятость залов, граничный бюджет, языки, форматы, часы, `null`, импорт CSV/JSONL и предлагаемые даты. Проверки исходного каталога фиксируют количество профилей, флаги и ожидаемые результаты сценариев.

Проверка синтаксиса JavaScript, если установлен Node.js:

```bash
node --check static/app.js
```

HTTP-проверка запущенного сервера, без изменения каталога:

```bash
python3 tests/smoke_api.py
```

## Структура и стек

```text
server.py             HTTP-сервер, API, загрузка каталога
matcher.py            Валидация и чистая функция подбора
dataset.py            Загрузка CSV/JSONL и нормализация полей
data/hackathon.csv    Исходные 66 профилей; каталог по умолчанию
generate_demo.py      Генерация демоданных
data/demo.jsonl       Дополнительные 66 синтетических демопрофилей
static/index.html    Структура приложения
static/styles.css    Адаптивный интерфейс

tests/test_matcher.py Тесты алгоритма
```

Backend: Python и стандартная библиотека. Frontend: HTML, CSS, обычный JavaScript. Каталог находится в памяти; импорт сохраняется атомарно в JSONL. Избранное сохраняется в браузере. Фильтрация линейная по числу профилей, затем сортируются подходящие. Сеть и внешние модели в подборе не участвуют.

## Ограничения и развитие

Версия использует объяснимый алгоритм на правилах. **LLM, эмбеддинги и AI-агенты не реализованы**. Семантический запрос, например «спокойный ведущий без конкурсов», пока не является параметром; описание показано для самостоятельного выбора.

Следующие шаги: добавить пожелания свободным текстом и семантическое ранжирование после жёстких фильтров; подтверждать смысловые совпадения цитатами из описаний; версионировать календари. Перед публичным размещением нужны production HTTP-сервер, авторизация импорта, лимиты запросов и проверка в браузерах.
